# Languages

Every screen reads in English, French and Norwegian Bokmål, the three languages of the stock GlitchTip UI. This page says how to add or change text so it stays that way.

## Adding text

1. Add the English string to the catalog of its area in `src/i18n/en/` (`common`, `shell`, `auth`, `account`, `projects`, `issues`, `releases`, `uptime`, `alerts`, `performance`, `logs`, `settings`). Each file is a plain object of strings and functions.
2. Add the same key to the matching files in `src/i18n/fr/` and `src/i18n/nb/`, in the same change. They are typed `Messages['area']`, so a missing key, an extra key or a changed argument fails `bun run typecheck`.
3. Read it in a component with `useT()`, which redraws the component when the language changes. Code outside a component (a notice, a page title, an error, a search index) calls `messages()` when it runs, never at module load.

Search syntax (`is:unresolved`, `level:error`) and the backend's field names stay as they are in every language; only the words around them change.

## Helpers

- **Plurals.** `plural(count, { one, other, many? })`, from `@/i18n`, picks the form with `Intl.PluralRules`. `#` is the formatted count. French puts 0 and 1 under `one` and a round million under `many` (`1 000 000 de problèmes`); Norwegian puts 0 under `other`. A count already worded (`1000+`) uses `other` as it is. A count set in mono beside its word uses `counted(count, forms, figure)` from `src/i18n/counted.tsx`, which swaps the leading `#` for the figure.
- **Action phrases.** A failure reads "Couldn't {action}. Try again." The action comes from the catalog of the area that failed (`renameAction: 'rename the project'`), so each language can build its own sentence: French joins it with "de" or "d’", Norwegian with "Kunne ikke".

## How the language is chosen

English is in the main bundle; French and Norwegian are one chunk each, fetched only by someone who reads them. `src/main.tsx` waits up to 2.5 seconds for `startLocale()` before the first render, so the first paint is normally already in the right language.

Profile → Language, and Language under More on a phone, offer "Same as browser" and each language under its own name, and the palette lists the other languages under `language`. The pick is saved to the account's `options.language` (which stock GlitchTip accepts but never reads), so it follows the user to another browser, and this browser keeps a copy in `localStorage.language`. With nothing chosen, Faultline takes the first of `navigator.languages` it has (`no` and `nn` read as Bokmål), else English (`src/lib/language-sync.ts`). Dates and numbers use the browser's own variant of the chosen language (`en-GB` stays `en-GB`), else the language itself.

## Style

- Keep the English as the source of meaning. When English uses one word for two jobs (`Set` as a button and as a value), split the key, since other languages need two words.
- A sentence with a name or link in it is one function that takes it (`notVerified: (email: ReactNode) => …`), never two halves joined in the component, so each language can order the words.
- Reuse the stock UI's terms where it has them: Problèmes / Problemer, Versions / Utgivelser, Équipes / Grupper, Alertes / Varsler, Paramètres / Innstillinger, Se connecter / Logg inn, clé de sécurité / sikkerhetsnøkkel, codes de récupération / gjenopprettingskoder. Stock's "Epost" is written "e-post", as Bokmål spells it now.
- **French.** A narrow no-break space (U+202F) before `?`, `!` and `;` and inside « », a no-break space (U+00A0) before `:` and between a number and its unit. Curly apostrophes (’). "Vous", not "tu". Sentence case.
- **Norwegian Bokmål.** « » for quotes, no space inside. "Du". Sentence case. "E-post", "e-postadresse".
